# 아이디어 — watchog 를 개인 비서로 확장한다

> 상태: **아이디어. 착수 안 함.** 2026-09-12 대화에서 나온 것을 잃지 않기 위해 적는다.
> 판정층(로드맵 4주차)이 서기 전에는 손대지 않는다. 그 전에 이걸 시작하면 알림 허브도 비서도 반쪽이 된다.

## 출발점 — 관찰

일반 사용자가 에이전트 앱을 비서로 쓰기엔 안 되는 게 너무 많다. 모델이 못해서가 아니라 **접근 권한**이 없어서다.

| 비서가 필요한 것 | 에이전트 앱이 못 하는 이유 |
|---|---|
| 내 폰에 온 알림을 읽기 | OS 가 알림 접근을 앱 단위로 막는다 (iOS 는 아예 불가) |
| 로그인된 서비스의 내 데이터 | 세션·2단계 인증·계정 제재. 서비스가 자동화를 원치 않는다 |
| 내가 안 보고 있을 때도 돌기 | 앱은 화면이 꺼지면 죽는다. 상시 프로세스가 없다 |
| 결과를 나한테 밀어 넣기 | 앱 안에서만 말한다. 폰 푸시·캘린더·문자로 나오지 않는다 |
| 행동 (예매·등록·답장) | 사이트마다 봇 차단. 행동은 곧 우회가 된다 |

즉 비서의 병목은 지능이 아니라 **들어오는 길과 나가는 길**이다.

## watchog 가 이미 갖고 있는 것

watchog 는 이 표의 "들어오는 길" 을 하나씩 뚫어 온 프로젝트다.

- 들어오는 길 (소스 5갈래): 피드·웹 · 이메일(로그인 필요한 서비스의 정답) · 폰 알림(Tasker → ntfy inbox) · LLM 검색
- 나가는 길: ntfy 푸시, 「유용/무시」 버튼으로 되돌아오는 피드백. 캘린더 동기화는 보류 중 (event 종류에 붙는 자리)
- 상시 실행: GitHub Actions + 로컬 Docker, 하트비트로 "멈춘 걸 모르는 상태" 방지
- 판정 원칙: 판정은 코드, LLM 은 접수와 서술만. 검증 통과 후에만 등록. 막힌 소스는 뚫지 않는다

비서로 가는 확장은 **새 프로젝트가 아니라 나가는 길과 판단을 넓히는 것**이다.

## 확장의 모양 (아직 결정 아님)

```
지금:   감시(들어옴) → 판정(코드) → 알림(나감)
비서:   감시 + 내 상태(캘린더·위치·게임 중) → 판정 + 우선순위 → 알림 + 행동 초안
```

- **내 상태를 입력으로**: 캘린더(비어 있는 시간), 게임 중(quiet: gaming 이 이미 그 씨앗), 위치(폰). "지금 이걸 알려도 되나"를 판단하는 재료
- **행동은 초안까지만**: 예매 페이지 열기, 캘린더 등록, 답장 초안, 장바구니 링크. **실행 버튼은 사람이 누른다.** 행동을 자동화하면 곧 차단 우회·계정 제재 문제로 돌아간다
- **하루 브리핑**: 다이제스트를 주제별이 아니라 "오늘 나한테" 기준으로 한 통. 이력 sqlite 와 피드백이 재료
- **대화 창구는 이미 있다**: MCP 서버. "오늘 뭐 있어?" 가 `history` 위에서 답해진다

## 지켜야 할 것 (비서가 돼도 바뀌지 않는 원칙)

1. 단일 사용자. 내 것만. 인증·요금·격리 없음
2. 데이터는 내 PC 와 내 레포(해시만)에. 폰 알림 원문·이메일 본문은 레포로 흘러가지 않는다
3. 권한은 내가 준 것만 쓴다. 우회하지 않는다 (ADR 0003). 못 하는 건 "못 한다"고 빨리 말한다
4. LLM 은 여전히 접수·서술·우선순위 제안까지. 행동의 실행은 사람

## 다시 볼 때

- 판정층(중복·다이제스트·threshold·event)이 서고 이력이 한 달쯤 쌓인 뒤
- 그때 첫 질문은 "하루 브리핑 한 통이 지금 알림 여러 통보다 나은가" — 이게 비서의 최소 단위다
