# 0002. 감시 카테고리는 코드 모듈이 아니라 레시피(yaml 데이터)로 둔다

| 상태 | 날짜 |
|---|---|
| **채택** | 2026-09-11 |

## 현상

08-18 설계는 `watchers/cgv.py`, `watchers/jobs.py` 처럼 주제마다 코드 모듈을 두는 구조였다. 이 구조에서는
새 주제(축구팀 일정, 공연)가 생길 때마다 코드를 짜야 하고, "사용자가 말하면 등록된다"는 v1 의 목표와 맞지
않는다. 1주차에 등록 스크립트를 두 개 쓰고 나서 이 문제가 드러났다 — 두 스크립트는 사실 같은 코드에 데이터만
달랐다.

## 결정

주제 하나 = `recipes/<name>.yaml` 파일 하나. 레시피가 무엇을(topic) · 어떤 종류로(kind) · 어디서(sources) ·
얼마나(every, mode) · 어디로(topic → ntfy) 를 전부 들고, 코드는 레시피를 읽어 등록·갱신·삭제하는 한 벌
(`watchog/recipes.py`)만 둔다. `verified` 날짜가 없는 레시피는 등록을 거부한다.

## 이유

- 새 주제는 LLM 이 파일 하나를 쓰는 일이 된다. 코드 생성이 아니라 데이터 생성이라 검증(`test_parse`)을 코드가 할 수 있다.
- 레시피가 정본이 되므로 changedetection.io 의 데이터가 날아가도 `recipes sync` 한 번으로 복구된다.
- 실행 위치(runner: local / actions)를 레시피 단위로 정할 수 있어 브라우저가 필요한 것만 PC 에 남긴다.

## 트레이드오프

- 판정 로직이 갈리는 지점(kind)은 여전히 코드다. 레시피는 "무엇을 볼지"까지고 "어떻게 판정할지"는 kind 별 코드 네 벌.
- yaml 필드가 계약이 된다. 필드를 바꾸면 레시피·MCP 서버·러너·문서를 같이 고쳐야 한다 (CLAUDE.md 계약 표).
