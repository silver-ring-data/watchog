# 0001. changedetection.io 는 로컬 PC 의 Docker 로 띄운다

| 상태 | 날짜 |
|---|---|
| **채택** | 2026-09-11 |

## 현상

감시 엔진 changedetection.io 는 상시 프로세스가 필요하다. 원래 실행 환경으로 정했던 GitHub Actions cron 은
매 실행이 새 컨테이너라 상태를 유지하는 서버를 둘 수 없다. 후보는 로컬 PC Docker, 태블릿, 저가 VPS 셋이었고,
2주 동안 결정이 안 나 구현이 시작되지 않았다.

## 결정

`docker-compose.yml` 로 로컬 PC 에 changedetection.io + 브라우저 컨테이너(sockpuppetbrowser)를 띄운다.
포트는 127.0.0.1 에만 바인딩하고, 데이터(`data/changedetection/`)는 gitignore 한다.

## 이유

- 비용 0, 지금 당장 시작할 수 있다. 결정을 미루는 비용이 호스팅 차이보다 컸다.
- Docker Desktop 이 이미 다른 프로젝트(mtt-tracker) 로 설치돼 있다.
- 항공권·CGV 는 JS 렌더링이 필요해 브라우저 컨테이너가 같이 떠야 하는데, 이건 저가 VPS 메모리에서 빡빡하다.
- 이 프로젝트의 알림은 "그날 안에 알면 되는" 수준이라 PC 가 꺼진 몇 시간의 공백을 감수할 수 있다.

## 트레이드오프

- PC 가 꺼져 있으면 감시도 멈춘다. 하트비트(설계 원칙 4)가 없으면 멈춘 걸 모른다 → 하트비트를 먼저 붙인다.
- 다시 볼 조건: 취소표처럼 분 단위 공백이 아까운 모듈이 실제로 쓰이기 시작하면 그 모듈만 상시 기기로 옮긴다.
